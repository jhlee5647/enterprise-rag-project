# 근거 없는 답 줄이기 설계 기록

#47 에픽(검색 정확도·지연 시간)을 마친 뒤, 권한 없는 부서의 질문에 근거 없이 답하는 문제를 다루는 에픽의 측정과 결정을 모은다. 결정의 근거는 여기에 두고, 스펙 이슈와 티켓은 이 문서의 절을 가리킨다.

## 0. 측정 조건

- 데이터·색인: 표본 9,000건, 청크 70,398개, 마스커 `gliner`, 색인은 dense + BM25 sparse 벡터([검색 기록](retrieval-improvement.md) 6.1).
- 검색: `hybrid`(dense 정확한 검색 + BM25, 코드에서 RRF, 상수 1, 각 후보 20개), `top_k` 5, ACL 필터 켬, 리랭커 없음.
- 평가셋: 48문항(다른 판본 28개), 질문마다 부서 3개로 실행해 144번. 권한 있는 실행 71번, 권한 없는 실행 73번.
- 답변 LLM: vLLM `Qwen3-8B`, `max_tokens` 1,024, temperature 0. 환경은 RunPod A40 48GB.

| 지표 | 값 (`runs/hybrid-53c`) |
|---|---|
| 검색 적중률 | 0.854 |
| 거부 정확도 | 0.603 (권한 없는 실행 73번 중 44번이 찾지 못함 응답) |
| 검색 누출률 | 0.0 |
| 검색 단계 중앙값 / p95 | 85 / 91 ms |
| 전체 중앙값 / p95 | 2,100 / 8,455 ms |

## 1. 근거 없는 답

권한 없는 실행은 질문한 부서가 정답 문서를 볼 수 없는 실행이다. 이때 질의응답기는 그 부서가 볼 수 있는 청크만 근거로 받으므로, 그 청크에 답이 없으면 찾지 못함 응답을 돌려줘야 한다.

예: 마케팅 부서만 볼 수 있는 문서에 Brand Cling의 설명이 있다. 규제 부서가 "Brand Cling은 무엇에 쓰나?"를 물으면, 규제 부서가 볼 수 있는 청크에는 매장 부착물 "Customer facing Cling"만 있다. 그런데 LLM은 "Brand Cling은 고객용 마케팅 도구로 문서에 명시돼 있다"고 답했다. 마케팅 문서가 새어 나간 것은 아니지만(검색 누출률 0.0), 근거에 없는 말을 했다.

- 권한 없는 실행 73번 중 29번에서 LLM이 답했다. 이 중 `dense`에서 `hybrid`로 바꾸며 새로 답한 7번만 판정했고, 2번은 정당한 답(그 부서가 볼 수 있는 문서에 실제로 답이 있음), 5번은 근거 없는 답이었다([검색 기록](retrieval-improvement.md) 6.1).
- 나머지 22번은 판정하지 않아 근거 없는 답이 모두 몇 번인지 모른다.
- 거부 정확도는 정당한 답도 감점하므로, 지표만으로는 개선을 가릴 수 없다. 그래서 권한 없는 실행의 답을 판정해 근거 없는 답의 수를 함께 잰다.

**근거 없는 답** (이 에픽에서 정하는 말): LLM의 답변 중 근거로 받은 청크에 없는 내용을 사실처럼 말한 답. 단어만 겹치는 청크를 늘려 해석한 경우를 포함한다.

## 2. 고치는 방식

| 후보 | 판단 |
|---|---|
| 리랭커 + 기준 점수 | 선택. 검색 후보를 질문과의 관련도로 다시 매겨, 관련이 낮은 청크(단어만 겹치는 청크)를 근거에서 뺀다. 남는 청크가 없으면 LLM을 부르지 않고 찾지 못함 응답을 돌려준다 |
| "근거가 약하면 답하지 말라" 프롬프트 | 정당한 답까지 거부할 수 있다. 리랭커 결과를 보고 다음 단계에서 |
| 답변 LLM 바꾸기 | 범위가 커 미룸 |

## 3. 리랭커 후보

| 후보 | 방식 | 판단 |
|---|---|---|
| `BAAI/bge-reranker-v2-m3` | cross-encoder, 약 5.7억 파라미터, 다국어 | 비교 대상. 널리 쓰이고 sentence-transformers의 CrossEncoder로 바로 쓴다 |
| `cross-encoder/ms-marco-MiniLM-L-6-v2` | cross-encoder, 약 2,200만 파라미터, 영어 | 비교 대상. 문서가 영어이고 매우 빠르다. 속도의 기준선 |
| `Qwen/Qwen3-Reranker-0.6B` | LLM 기반(정해진 프롬프트로 "예/아니오" 확률을 읽음) | 이번에는 뺌. 임베딩과 같은 계열이지만 연결이 복잡해 시간이 더 든다 |
| 답변 LLM(Qwen3-8B)으로 점수 매기기 | 청크마다 vLLM에 관련 여부를 물음 | 뺌. 후보 20개마다 LLM을 불러 느리다 |

- 리랭커는 Pod 안에서 돈다(ADR-0002). `hybrid` 결과의 상위 20개를 받아 (질문, 청크 본문) 쌍마다 점수를 매기고, 점수 순으로 상위 k개를 고른다.
- **기준 점수는 0.5로 정해 둔다.** 리랭커 점수를 시그모이드로 0~1 확률로 바꾸고, 관련 있을 확률이 0.5 미만인 청크를 뺀다. 측정으로 값을 고르지 않고 일반적인 기준을 쓴다.
- **모델은 미리 정한 규칙으로 고른다.** 근거 없는 답이 더 적은 쪽을 고르고, 같으면 검색 단계가 빠른 쪽을 고른다. 검색 적중률이 지금(0.854)보다 0.05 넘게 떨어지는 후보는 뺀다.

## 4. 답변 확인

리랭커를 켜면 근거에서 빠지는 청크가 생겨 답이 부실해질 수 있다. 바꾼 뒤 권한 없는 실행에서 답한 것을 다시 판정하고(정당한 답 / 근거 없는 답), 권한 있는 실행 중 찾지 못함 응답으로 바뀐 실행을 함께 본다.

## 5. 미루는 것

- "근거가 약하면 답하지 말라" 프롬프트
- 답변 길이 줄이기(지연 시간). 리랭커가 들어가면 LLM에 넘기는 글과 찾지 못함 응답이 바뀌어 생성 시간도 달라지므로, 리랭커 결과를 본 뒤에 한다
- `Qwen3-Reranker` 등 다른 리랭커 비교, 답변 LLM 바꾸기
- 문서 날짜 반영, RRF 상수·비중 조정([검색 기록](retrieval-improvement.md) 6.1의 남은 것)
