# 근거 없는 답 줄이기 설계 기록

#47 에픽(검색 정확도·지연 시간)을 마친 뒤, 권한 없는 부서의 질문에 근거 없이 답하는 문제를 다루는 에픽의 측정과 결정을 모은다. 결정의 근거는 여기에 두고, 스펙 이슈와 티켓은 이 문서의 절을 가리킨다.

## 0. 측정 조건

- 데이터·색인: 표본 9,000건, 청크 70,398개, 마스커 `gliner`, 색인은 dense + BM25 sparse 벡터([검색 기록](retrieval-improvement.md) 6.1).
- 검색: `hybrid`(dense 정확한 검색 + BM25, 코드에서 RRF, 상수 1, 각 후보 20개), `top_k` 5, ACL 필터 켬, 리랭커 없음.
- 평가셋: 48문항(다른 판본 28개), 질문마다 부서 3개로 실행해 144번. 권한 있는 실행 71번, 권한 없는 실행 73번.
- 답변 LLM: vLLM `Qwen3-8B`, `max_tokens` 1,024, temperature 0. 환경은 RunPod A40 48GB.

| 지표 | 값 (`runs/hybrid-53c`) |
|---|---|
| 검색 적중률 | 0.854 |
| 거부 정확도 | 0.603 (권한 없는 실행 73번 중 44번이 찾지 못함 응답) |
| 검색 누출률 | 0.0 |
| 검색 단계 중앙값 / p95 | 85 / 91 ms |
| 전체 중앙값 / p95 | 2,100 / 8,455 ms |

## 1. 근거 없는 답

권한 없는 실행은 질문한 부서가 정답 문서를 볼 수 없는 실행이다. 이때 질의응답기는 그 부서가 볼 수 있는 청크만 근거로 받으므로, 그 청크에 답이 없으면 찾지 못함 응답을 돌려줘야 한다.

예: 마케팅 부서만 볼 수 있는 문서에 Brand Cling의 설명이 있다. 규제 부서가 "Brand Cling은 무엇에 쓰나?"를 물으면, 규제 부서가 볼 수 있는 청크에는 매장 부착물 "Customer facing Cling"만 있다. 그런데 LLM은 "Brand Cling은 고객용 마케팅 도구로 문서에 명시돼 있다"고 답했다. 마케팅 문서가 새어 나간 것은 아니지만(검색 누출률 0.0), 근거에 없는 말을 했다.

- 권한 없는 실행 73번 중 29번에서 LLM이 답했다. 이 중 `dense`에서 `hybrid`로 바꾸며 새로 답한 7번만 판정했고, 2번은 정당한 답(그 부서가 볼 수 있는 문서에 실제로 답이 있음), 5번은 근거 없는 답이었다([검색 기록](retrieval-improvement.md) 6.1).
- 나머지 22번은 판정하지 않아 근거 없는 답이 모두 몇 번인지 모른다.
- 거부 정확도는 정당한 답도 감점하므로, 지표만으로는 개선을 가릴 수 없다. 그래서 권한 없는 실행의 답을 판정해 근거 없는 답의 수를 함께 잰다.

**근거 없는 답** (이 에픽에서 정하는 말): LLM의 답변 중 근거로 받은 청크에 없는 내용을 사실처럼 말한 답. 단어만 겹치는 청크를 늘려 해석한 경우를 포함한다.

## 2. 고치는 방식

| 후보 | 판단 |
|---|---|
| 리랭커 + 기준 점수 | 선택. 검색 후보를 질문과의 관련도로 다시 매겨, 관련이 낮은 청크(단어만 겹치는 청크)를 근거에서 뺀다. 남는 청크가 없으면 LLM을 부르지 않고 찾지 못함 응답을 돌려준다 |
| "근거가 약하면 답하지 말라" 프롬프트 | 정당한 답까지 거부할 수 있다. 리랭커 결과를 보고 다음 단계에서 |
| 답변 LLM 바꾸기 | 범위가 커 미룸 |

## 3. 리랭커 후보

| 후보 | 방식 | 판단 |
|---|---|---|
| `Qwen/Qwen3-Reranker-0.6B` | LLM 기반 리랭커(약 6억 파라미터). 질문·문서가 관련 있으면 "yes"로 답하도록 학습됨 | 비교 대상. 지금 쓰는 임베딩 모델(Qwen3-Embedding)과 같은 계열의 최신 리랭커 |
| `BAAI/bge-reranker-v2-m3` | cross-encoder(약 5.7억 파라미터), 다국어 | 비교 대상. 오래 널리 쓰여 온 표준 cross-encoder |
| `cross-encoder/ms-marco-MiniLM-L-6-v2` | cross-encoder(약 2,200만 파라미터), 영어 | 뺌. 오래되고 작은 모델이다. 장점인 속도는 아래 측정처럼 세 후보 모두 수십 ms라 답변 생성(수 초)에 비해 차이가 작다 |
| 답변 LLM(Qwen3-8B)으로 점수 매기기 | 청크마다 vLLM에 관련 여부를 물음 | 뺌. 후보 20개마다 LLM을 불러 리랭커보다 훨씬 느리다 |

세 리랭커 모두 sentence-transformers의 CrossEncoder로 같은 방식으로 불러진다(6.2 기준). Pod에서 질문 1개 × 청크 20개의 점수를 낸 시간(예열 뒤)과 관련 있는 청크 / 없는 청크의 점수:

| 모델 | 시간 | 점수 |
|---|---|---|
| `Qwen/Qwen3-Reranker-0.6B` | 58 ms | 10.9 / −10.2 (로짓) |
| `BAAI/bge-reranker-v2-m3` | 30 ms | 0.987 / 0.000 (확률) |
| `cross-encoder/ms-marco-MiniLM-L-6-v2` | 약 19 ms | 6.4 / −11.4 (로짓) |

- 리랭커는 Pod 안에서 돈다(ADR-0002). `hybrid` 결과의 상위 20개를 받아 (질문, 청크 본문) 쌍마다 점수를 매기고, 점수 순으로 상위 k개를 고른다.
- **기준 점수는 0.5로 정해 둔다.** 모델마다 점수 범위가 달라(로짓 / 확률) 모두 0~1 확률로 맞추고, 관련 있을 확률이 0.5 미만인 청크를 뺀다. 측정으로 값을 고르지 않고 일반적인 기준을 쓴다.
- **고르는 기준**: 근거 없는 답이 얼마나 줄었는지, 검색 적중률이 지금(0.854)만큼 유지되는지, 검색이 얼마나 느려지는지를 함께 본다. 리랭커 없음도 후보로 놓고 비교한다.

### 3.1 결과 (#63, #64)

같은 색인과 평가셋(48문항)으로 `hybrid` 검색에 리랭커를 붙여 쟀다. 권한 없는 실행에서 LLM이 답한 것은 독립 검수 에이전트 3명이 정당한 답 / 근거 없는 답으로 판정하고, 의견이 갈리거나 일부만 근거가 있는 답은 사람이 정했다(다른 직책·날짜의 내용을 묻는 대상의 내용처럼 말한 답은 근거 없는 답).

| 지표 | 리랭커 없음 (`hybrid-53c`) | Qwen3-Reranker (`rerank-qwen-64`) | bge-reranker (`rerank-bge-64`) |
|---|---|---|---|
| 검색 적중률 | **0.854** | 0.796 | 0.784 |
| 거부 정확도 | 0.603 | 0.562 | **0.781** |
| 근거 없는 답 (권한 없는 실행 73번 중) | 15 | 22 | **6** |
| 정당한 답 | 14 | 10 | 10 |
| 권한 있는 실행이 찾지 못함으로 바뀜 | 0 | 0 | 7 |
| 검색 단계 중앙값 / p95 | **85 / 91 ms** | 414 / 427 ms | 620 / 706 ms |
| 전체 중앙값 / p95 | 2,100 / 8,455 ms | 2,749 / 10,232 ms | 1,935 / 10,347 ms |
| 검색 누출률 | 0.0 | 0.0 | 0.0 |

- **Qwen3-Reranker**는 단어만 겹치는 청크에도 높은 점수를 줬다. 예: 규제 부서의 Brand Cling 질문에서 "Customer facing Cling" 청크에 0.974. 근거 없는 답이 15번에서 22번으로 늘고 검색 적중률도 떨어졌다.
- **bge-reranker**는 근거 없는 답을 15번에서 6번으로 줄였다. 대신 기준 점수 0.5가 맞는 정답 문서까지 빼, `hybrid`만으로는 정답을 찾던 권한 있는 실행 7번이 찾지 못함으로 바뀌었다. 그 정답 문서들의 점수는 0.09~0.47이었고, 오타가 많은 질문("Whot is a communnication plen…")에서 특히 낮았다.
- 두 리랭커 모두 검색 단계가 0.3~0.5초 늘었다(후보 20개마다 점수를 매김). bge는 찾지 못함 응답이 늘어 LLM을 덜 불러 전체 중앙값은 줄었다.
- GPU 메모리는 리랭커를 띄운 뒤 30,191MiB(vLLM 포함)였다.

**결정: 리랭커를 켜지 않는다(사람이 결정).** 세 방식 중 리랭커 없음이 지금 가장 적합하다.
- 검색 적중률이 가장 높고, 권한 있는 사용자가 맞는 답을 잃는 경우가 없으며, 검색이 가장 빠르다.
- Qwen3-Reranker는 모든 지표에서 리랭커 없음보다 나쁘다.
- bge-reranker는 근거 없는 답을 크게 줄이지만, 그 대가로 권한 있는 사용자가 맞는 답을 받지 못하는 경우(7번)와 검색 적중률 0.07 하락, 검색 0.5초 증가가 생긴다. 근거 없는 답을 줄이려다 맞는 답을 잃는 것은 지금 기준 점수에서는 득보다 실이 크다.
- bge가 근거 없는 답을 줄이는 효과는 뚜렷해 다음 단계 후보로 남긴다(기준 점수를 bge의 점수 분포에 맞게 다시 보기, 리랭커 점수를 청크를 빼는 데가 아니라 답할지 말지 판단하는 데만 쓰기).

## 4. 답변 확인

리랭커를 켜면 근거에서 빠지는 청크가 생겨 답이 부실해질 수 있다. 바꾼 뒤 권한 없는 실행에서 답한 것을 다시 판정하고(정당한 답 / 근거 없는 답), 권한 있는 실행 중 찾지 못함 응답으로 바뀐 실행을 함께 본다.

## 5. 미루는 것

- "근거가 약하면 답하지 말라" 프롬프트
- 답변 길이 줄이기(지연 시간). 리랭커가 들어가면 LLM에 넘기는 글과 찾지 못함 응답이 바뀌어 생성 시간도 달라지므로, 리랭커 결과를 본 뒤에 한다
- 더 큰 리랭커(예: Qwen3-Reranker 4B·8B) 비교, 답변 LLM 바꾸기
- 문서 날짜 반영, RRF 상수·비중 조정([검색 기록](retrieval-improvement.md) 6.1의 남은 것)
